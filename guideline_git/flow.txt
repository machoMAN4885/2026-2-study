(3)각 명령어 한 줄 설명

git clone
→ GitHub 저장소를 내 컴퓨터에 처음 복제

git pull
→ GitHub의 최신 변경사항을 내 컴퓨터로 가져오기

git status
→ 어떤 파일이 수정/추가/삭제되었는지 확인

git add .
→ 현재 변경사항들을 다음 커밋 대상으로 준비

git commit -m "메시지"
→ 변경사항을 Git 기록으로 저장

git push
→ 내가 만든 커밋을 GitHub에 업로드

git log --oneline
→ 지금까지의 커밋 기록을 간단히 확인

(4) add -> commit -> push

파일 수정
↓

↓
git commit
↓
"이 시점의 작업 상태를 기록"
↓
git push
↓
"그 기록을 GitHub에 업로드"

(5) git pull과 git push

GitHub
   ↓
git pull
   ↓
내 컴퓨터

pull = 원격 → 로컬

내 컴퓨터
   ↓
git push
   ↓
GitHub

(6) 커밋 메시지는 어디에 쓰나

git commit -m "Add neural network course folder"

GitHub에 push하면 이 메시지도 기록으로 남음.

"Add neural network week 1 practice"
"Update Linux permission notes"
"Fix FastAPI routing example"

처럼 무엇을 바꿨는지 짧게 쓰기.

(7) ETC

README.md = 사람에게 보여주는 폴더/프로젝트 설명서

.gitignore -> 

.venv/
→ Python 가상환경 제외

__pycache__/
→ Python 자동 생성 캐시 제외

.env
→ 비밀번호/API Key 등이 들어갈 수 있으므로 제외

*.log
→ 로그 파일 제외


개발환경 자체는 GitHub에 올리는 게 아니다

대신: 
requirements.txt
README.md
Dockerfile
설정 파일
같이 환경을 다시 만들 수 있는 정보를 올린다.
